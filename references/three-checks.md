# 三检清单

每条候选逐项检查，结果写 **通过 / 待改 / 淘汰 ＋ 一句原因**。检一、检二任一项"淘汰"，该候选直接出局，不能靠其他优点抵消。

---

## 检一 · 正文兑现

- [ ] 标题里的每一项承诺（对象、动作、结果、答案）都能指向正文的具体段落或小节。
- [ ] 标题的颗粒度和正文一致：标题说"怎样做到"，正文确实讲了做法，而不只是讲结果。
- [ ] 窄角度能否代表全文？如果只代表某一节，要在风险里写明，或建议作者调整正文重心（由作者决定，本 skill 不改正文）。
- [ ] 标题露出的"一点答案"在正文里有展开。
- [ ] 没有承诺正文给不出的东西（"全攻略""照做就行""所有人都适用"）。

无法兑现时：淘汰，或标「待补证：需要正文补充 ___」。

## 检二 · 事实口径

- [ ] **对象**：公司、产品、人物名称准确；没有把子产品写成整个公司。
- [ ] **动作**：确实是对象做了这件事，而不是第三方、媒体或作者推断。
- [ ] **因果**：正文是"相关/可能"时，标题不能写成"因为/靠/导致"的确定因果。
- [ ] **比较范围**：市场、地区、人群、时间段写清楚；"某细分市场第一"不能缩成"第一"。
- [ ] **数字**：最多一个主数字；时间、分母、来源可查；区分：
  - 估计 vs 官方披露
  - 收入 vs 年化收入（ARR/run-rate）
  - 周活 vs 月活 vs 注册用户
  - 收入留存 vs 用户留存
  - 版本号、年份不是成绩，不当数据钩子
- [ ] **限定写不下就不用数字**。没有数字也完全合格。
- [ ] 没有假独家、假实测、假内部消息、假时效词。
- [ ] 没有补造正文没有的身份、经历、结果。

## 检三 · 手机截断＋去 AI 味

### A. 手机截断与平台适配

- [ ] 对象和核心问题尽量放在标题前半段。
- [ ] 前半截单独看，能否读懂"谁、什么问题"？（这只是粗略压力测试，不代表平台真实截断位置。）
- [ ] 公众号：在实际编辑器或预览里看列表/会话卡片的显示效果；标题字数上限以编辑器实际限制为准。
- [ ] X Article：看文章卡片和时间线里的实际显示；不要把推文/线程开头的写法当成长文标题。
- [ ] 没有实机预览就标「待实机预览」，不声称已验证，不编造固定截断阈值。
- [ ] 英文产品名可以保留，但删掉冗余修饰；英文逐字母计数不等于手机显示宽度。
- [ ] 两个平台可以用不同的配帖首句，但不擅自改作者选定的正文标题。

长度参考：见 [examples.md](examples.md) 中的公开样本长度观察，仅作参考，不是硬指标或胜率结论。

### B. 去 AI 味

朗读一遍，删掉或改写：

| 类型 | 例子 | 改法 |
|---|---|---|
| 空口号 | 赋能、范式跃迁、增长奇迹、重新定义、开启新篇章 | 换成具体动作："让团队把周报交给它" |
| 新闻腔时效词 | 刚刚、突发、连夜、重磅、炸了 | 案例复盘类长文不用；确有时效且属实才考虑 |
| 夸张/对抗 | 碾压、血洗、彻底颠覆、降维打击、史上最强 | 删除，或换成有证据的具体比较 |
| 半中半英黑话 | PLG 飞轮、GTM 闭环、Agentic 增长 | 换白话："靠用户自己带进公司" |
| 翻译腔 | "一个关于……的故事""这就是为什么……" | 直接说问题和答案 |
| 空壳悬念 | 到底做对了什么、真相竟然是、看完沉默了 | 露出一点答案 |
| 无据许诺 | 必看、收藏、看完赚翻、普通人逆袭 | 删除 |
| 堆砌标点 | ！！、？！、多个引号 | 最多一个问号或一处引号 |

保留：必要的公司名、产品名、专有名词，不为"去英文"而改错名字。

## 编辑维度（排序用，不打分）

过完三检后，对通过的候选逐项写一句判断：

1. **清晰**：第一次看到的人，能否读懂谁、什么问题？
2. **具体**：有真实动作或场景，而不是"增长之道"？
3. **真实好奇心**：有值得解释的差异吗？是否露出一点答案？
4. **角度差异**：与本组其他候选真是不同的观察角度吗？
5. **全文代表性**：标题和正文的重心一致吗？

再用三个读者视角各挑一次刺：怀疑者（是真的吗）、懂行的人（说法准确吗）、编辑（承诺与正文一致吗）。

不生成"综合得分""预计点击率提升 X%"之类的伪精确数字。
